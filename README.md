# LidGen

Веб-приложение на GitHub Pages для хранения и выдачи сообщений лидам. База — Supabase (Postgres + Auth + RLS). Никаких ботов и автоматических рассылок: приложение только хранит ссылки и тексты и отмечает, кому уже написали.

**Адрес:** https://g0shan4ik.github.io/lidgen/

Повседневная работа описана ниже; технические детали — в конце.

---

## Вход

Регистрации нет. Учётные записи создаёт админ и передаёт логин/пароль лично.

- Логин — то, что выдал админ (регистр не важен).
- Пароль — от 8 символов.

## Главное меню

| Кнопка | Что делает |
|---|---|
| ➕ Добавить лид | выбрать категорию (бургер ☰), ввести ссылку на соцсеть и текст сообщения, «Сохранить» |
| 🗑 Удалить лид | категория → список лидов → «Удалить» с подтверждением |
| ✏️ Изменить лид | категория → список лидов → правка ссылки, текста и категории |
| 📨 Получить лид | категория → список **ещё не отправленных** лидов → карточка лида |
| 🗂 Создать категорию | создание и удаление категорий (удаление — с подтверждением, вместе с лидами) |
| 📊 Статистика | сводка по пользователям за день / 3 дня / неделю / месяц / всё время + лента действий |
| ⚙️ Настройки | твой профиль, выход; у админа — создание пользователей и их список |

## Карточка лида («Получить лид»)

- **Ссылка на соцсеть** — нажатие открывает её в новой вкладке.
- **Текст сообщения** — нажатие копирует его в буфер обмена.
- Дата создания и автор.
- **«✅ Лид получил письмо»** — с подтверждением. После этого лид помечается (кто и когда) и **пропадает из выдачи**, чтобы не написать повторно. В списках просмотра он остаётся с меткой «письмо отправлено».

## Категории и лиды

- У лида обязательны: категория, ссылка, текст. Без любого из них сохранение не проходит.
- В списках текст показывается обрезком в две строки; нажатие на обрезок раскрывает его полностью.
- Один лид = одна ссылка; повторы внутри категории не запрещены, но держи порядок руками.

## Статистика и лента

Считаются действия всех пользователей, включая админа: добавил лидов, отправил писем, изменил, удалил, создал/удалил категорий. Период переключается чипами. Строка текущего пользователя подсвечена. Ниже — лента: кто и что сделал, с датой и временем. Лента видна всем вошедшим.

## Админ

- Видит в настройках блок «Создать пользователя»: имя, логин, пароль. Логин — 3–30 символов `A-Z a-z 0-9 . _ -`, пароль от 8 символов.
- Создание идёт через серверную Postgres-функцию `admin_create_user`: она проверяет роль вызывающего, создаёт аккаунт в Supabase Auth и профиль. Пароли хранятся только в виде bcrypt-хеша.
- Список текущих пользователей — там же.
- Удаление пользователя сейчас не предусмотрено в интерфейсе (при необходимости выполняется администратором базы).

## Технически

### Стек

- **GitHub Pages** — статический фронтенд (vanilla JS, без сборщика), мобильная вёрстка первична.
- **Supabase** — Postgres, Auth, Row Level Security.
- Создание пользователей — Postgres-функция `SECURITY DEFINER` (Edge Functions на этом проекте не стартуют, поэтому выбран серверный SQL-путь).

### Таблицы

| Таблица | Назначение |
|---|---|
| `profiles` | id → auth.users, login, name, role (`admin`/`user`) |
| `categories` | имя категории, автор, дата |
| `leads` | категория, ссылка, текст, автор, даты создания/правки, `sent_at`/`sent_by` |
| `activity` | журнал: кто, что, с чем, когда |

RLS: все четыре таблицы доступны только аутентифицированным; запись журнала и создание лидов/категорий — любому вошедшему; создание пользователей — только через функцию с проверкой роли.

### Ключи и сроки

- `anon`-ключ вшит в `config.js` и публичен по замыслу; его срок — 2036 год.
- `service_role` нигде в клиенте не находится: он используется только внутри Postgres-функции и в моих терминальных операциях.
- `sbp_…` — персональный токен менеджмента Supabase (схема, деплой). **На работу сайта не влияет.** Срок жизни задаётся при создании токена в дашборде Supabase (там же, где ты видел «7 дней»). Когда истечёт — просто выпусти новый и продолжишь админ-операции; приложение не заметит.

Проверка доступности и сроков: `lidgen-tests/check-tokens.ps1`. Автоматический пинг сайта и Supabase каждые 6 часов — workflow `health` (при падении создаёт issue).

### Локальный запуск и тесты

```powershell
python -m http.server 8123 --directory lidgen
cd lidgen-tests
npx playwright test          # 18 тестов: функционал на мобильном + адаптивность mobile/desktop
```

Тесты идут против боевого Supabase с тестовыми сущностями (`ZZ …`), которые удаляются в `afterAll`.
